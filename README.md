# 被看见 · 商家观察台

Python 后端、独立 React 前端的商家搜索发现与证据探索工具。

公开落地页 → 对话中的商家模板 → 快速发现报告 → 全屏三维证据网络 → 自由追问。

确认顾客需求、搜索覆盖测评、推荐盲测和竞品追查变为可选模板，不再是必经步骤。首次发现执行 1 条基础查询、4 条带探店/体验/推荐文章意图的需求查询，再做 1 次品牌资料补充。如果只见榜单或门店目录，可额外补充最多2条文章搜索，不生成测评百分比。报告主线是逐查询的名称提及、公开内容与宣传参考，商家身份不是开始搜索或分析内容的前置条件。

页面遵循用户指定的 `frontend-design` skill，设计取舍见 [DESIGN.md](DESIGN.md)。工程不内置假搜索结果；缺少密钥时显示明确配置提示。合成数据仅存在于 `backend/tests`，不提供线上模拟模式。

## 运行环境

- Python 3.12（本次在 3.12.13 验证）。
- Node.js 22，npm。
- 已开通的元宝搜索标准版或旗舰版及腾讯云 SecretId / SecretKey。
- 支持 `/chat/completions` 的 OpenAI 兼容模型服务。建议使用能稳定遵守 JSON 格式、具有足够上下文长度的模型。

接口要求来自[腾讯云 SearchPro 官方文档](https://cloud.tencent.com/document/product/1806/121811)。工程固定 `Mode=0`、`Cnt=10`，不传 `Freshness`，读取标题、标准摘要与动态摘要，不抓取网页全文。

## 本地启动

在项目根目录执行以下安装步骤。Windows 可以使用 `py -3.12` 或你已安装的 Python 3.12 可执行文件；本次工作区的 `.venv` 已创建。

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r backend\requirements.txt
cd frontend
npm.cmd ci
cd ..
if (!(Test-Path .env)) { Copy-Item .env.example .env }
```

编辑根目录 `.env`，填写：

```dotenv
DEMO_PASSWORD=替换为你的工作空间口令
TENCENTCLOUD_SECRET_ID=腾讯云密钥ID
TENCENTCLOUD_SECRET_KEY=腾讯云密钥
BASE_URL=https://你的模型服务地址/v1
API_KEY=模型密钥
MODEL=模型名称
```

`BASE_URL` 填服务商要求的版本前缀，代码在末尾追加 `/chat/completions`。不要将完整的 `/chat/completions` 路径重复填入。密钥只保留在服务端；无需发到聊天或写入前端。

先运行真实连通性检查（会消耗 **一次元宝搜索及一次模型调用**）：

```powershell
cd backend
..\.venv\Scripts\python.exe -m app.preflight
```

如果暂时只配置了元宝搜索，可先单独验证（仅发起一次搜索请求）：

```powershell
..\.venv\Scripts\python.exe -m app.preflight --search-only
```

若出现 `WinError 10013`，表示当前进程的网络访问被权限策略阻止，尚不能判断腾讯云凭据是否有效。需要在运行环境中允许联网，或从已获联网权限的本机终端运行同一检查；不要关闭 TLS 校验。

分别在三个终端启动，或在安装后使用根目录的 `scripts/Start-Local.ps1`：

```powershell
# 终端 1，工作目录 backend
..\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000

# 终端 2，工作目录 backend
..\.venv\Scripts\python.exe -m app.worker

# 终端 3，工作目录 frontend
npm.cmd run dev
```

打开 [本地应用](http://127.0.0.1:5173)。如果尚未配置 `.env`，开发环境默认工作空间口令为 `be-seen-local`。只绑定回环地址，公开部署前应更换口令并配置 HTTPS。

前端代理到 `127.0.0.1:8000`。开发测试可以用环境变量 `API_PROXY_TARGET` 改变代理目标；这不是模型服务地址。

## Docker Compose

填写 `.env` 并启动 Docker 引擎后，在根目录执行：

```bash
docker compose up --build -d
docker compose logs -f worker
```

应用位于 [本地容器入口](http://127.0.0.1:8080)。Compose 包含 Nginx 前端、FastAPI、独立 Worker，SQLite 存在 `beseen-data` 持久化卷。API 不直接映射到宿主公网。

```bash
docker compose down
```

上述命令保留数据库卷；不要使用 `down -v`，除非确实要删除报告。单机只运行一个 Worker，OS 文件锁防止同时启动多个 Worker。首次升级建议先备份数据库；本版暂无数据库版本迁移需求。

## 使用方式

1. 填商家名称、城市和主营品类，可补充区县、标签、服务方式、价位、别名和官网。
2. 系统用最多三次含品牌名的查询建立档案。这些结果不进入曝光统计。
3. 核对搜索提出的补充资料，选择采纳或保留不确定。若新资料影响需求场景，点击“保存并重新生成”。
4. 编辑四组各六个场景。顾客问题和搜索词不能含目标品牌、别名、官网域名或完整门店地址；查询必须含城市。
5. 点击“确认并开始测评”，冻结商家资料、计划版本和配置。刷新页面可恢复观察。
6. 在报告中展开每个场景，查看搜索摘要、实体识别、候选推荐及独立核验后的结果。可取消后续步骤、导出 JSON、打印报告。
7. 同一场景集合可重新测评。新实验不覆盖旧报告，可从报告底部“历次测评”查看历史。

修改商家名称、城市或主营品类需要新建分析，避免复用错误的建档来源。填写完整门店地址会切换为单店口径，地址不明确匹配时保留疑似或其他门店状态。

## 测量口径

| 指标 | 分子 | 分母 |
|---|---|---|
| 搜索场景覆盖率 | 确认发现目标商家的场景数 | 搜索成功的场景数 |
| 前三条结果覆盖率 | 前三条结果确认提及目标的场景数 | 搜索成功的场景数 |
| 模拟推荐入选率 | 核验后的推荐包含已确认目标的场景数 | 完成实体与推荐核验的场景数 |

- 成功返回零条结果是有效搜索；没有证据时正常弃答。HTTP 错误不计入有效搜索分母。
- 身份核验失败标记“身份核验失败”，不伪装“未发现”；该场景尚不能计入确认命中，报告给出未核验数量。
- 疑似提及与同品牌其他门店分别展示。比例采用已确认口径，未确证的命中可能使实际可见度被低估。
- 一个场景中重复出现不重复计数。独立来源使用规范化 URL 去重，去除跟踪参数，并额外统计域名。
- 商家首次提及位置是包含它的搜索结果位置，不是商家之间的排名。相关性 `score` 不参与知名度计算。
- 推荐模型只收到顾客问题和证据。独立核验模型再次只收到问题、证据、候选推荐，检查商家身份、需求匹配和推荐理由；它也不知道测评对象。
- 程序核验引用编号、原文片段和商家名称。模型核验仍可能犯错，证据链供人工复核，不构成真实性保证。
- 场景生成和文字归一化去重可以减少重复，无法证明所有自然语言场景语义完全独立；用户确认页仍是必要校准步骤。
- 搜索摘要不等于网页全文；链接存在不代表已验证可打开；系统不承诺抓取登录后平台内容。
- 结果只代表本次时间、查询、搜索服务和模型配置下的实验，不代表真实搜索流量、全网知名度或其他 AI 产品。

## 任务与预算

- 典型搜索总数：建档 3＋场景 24＋竞品最多 6＝33；含失败重试硬上限 40。
- 模型典型最大调用数：建档与规划 2＋场景识别 24＋推荐 24＋独立核验 24＋建议 1＝75；含重试硬上限 80。空结果、弃答会少用调用。
- 重新生成计划也消耗同一分析预算。每次新运行计入其建档阶段已经使用的预算，以保守方式限制总调用；这不是账户账单。
- 搜索并发最多 3，模型并发最多 2。网络超时、限流和临时错误最多重试 2 次。JSON 校验失败会附带修正说明再尝试，避免重复发送同一个无效请求。
- 搜索 20 秒超时，模型 60 秒超时。SDK 连接故障可能额外受到系统网络超时影响，不承诺固定完成时间。
- 所有调用前先记预算，完成后写检查点。重启只续跑未完成步骤；已保存搜索不再次请求。请求成功但本地还未落库时中断可能导致重复计费。
- 查询、原始响应、时间、请求 ID、模型输入、输出、实际返回模型名、提示词版本和错误均保存在审计记录。原始搜索完整保存；模型证据文本每字段截取最多 2400 字符，建议模型使用有界证据样本，避免把 24 份完整检索结果一次塞入上下文。
- 前端每 2 秒轮询；实际外部调用全部由 Worker 发起。API 退出或浏览器关闭不会删除任务。

## API 与数据

交互式接口文档：[FastAPI 文档](http://127.0.0.1:8000/docs)。业务端点使用 `Authorization: Bearer <session token>`；`POST /api/v1/auth/session` 验证工作空间口令后签发 12 小时会话。

| 方法与路径 | 行为 |
|---|---|
| `GET /api/v1/health` | 配置状态，不回传密钥，不代表真实连通 |
| `POST /api/v1/analyses` | 提交商家资料，创建异步建档任务 |
| `GET /api/v1/analyses` | 最近 30 个分析及其最新测评 |
| `GET /api/v1/analyses/{id}` | 档案、建议、计划和进度 |
| `PATCH /api/v1/analyses/{id}/plan` | 带 expected_version 保存档案、场景及采纳的建议 |
| `POST /api/v1/analyses/{id}/regenerate` | 显式重试失败建档或重新生成场景 |
| `POST /api/v1/analyses/{id}/runs` | 传 plan_version 及 Idempotency-Key，冻结并启动 |
| `GET /api/v1/analyses/{id}/runs` | 同一分析的历次测评 |
| `GET /api/v1/runs/{id}` | 进度和调用计数 |
| `POST /api/v1/runs/{id}/cancel` | 停止后续调度，保留已完成步骤 |
| `GET /api/v1/runs/{id}/report` | 完整或部分报告 |
| `GET /api/v1/runs/{id}/evidence?scenario_id=s01` | 指定场景执行输入、原始响应与证据 |
| `GET /api/v1/runs/{id}/export` | 下载含审计记录的 JSON |

原有实验表为 `analyses`、`runs`、`task_steps`；新版会话和产物表见下文。Profile、Plan、Evidence、EntityMatch、Recommendation 等以 Pydantic 校验的 JSON 快照存储，便于保留完整实验记录。正式多租户产品可以再拆分检索与证据索引表。

## 对话与可视化版本（2026-10-25）

- `/` 是公开的方法落地页；`/chat/new` 进入受口令保护的首次商家模板；`/chat/:id` 恢复对话；`/reports/:id` 全屏探索报告。
- 新增 SQLite 表 `conversations`、`messages`、`chat_tasks`、`artifacts`。首次启动自动添加，不删除旧表；历史报告仍能通过会话侧栏打开。部署前备份 SQLite 文件及 WAL，或停止服务后备份。
- 对话提交必须带 `Idempotency-Key`。服务端事务检查同一会话仅允许一个运行任务；取消保留已完成步骤。用户点击重试会创建新任务并重新计费，界面明确提示；Worker 意外重启则复用原任务检查点。
- 首次报告最多8次正常搜索（5条需求、1条品牌、按需2条文章补充）；竞品追查最多6次。两者含重试的搜索上限12、模型上限12。自由追问：含重试搜索上限 6，模型上限 12。完整实验沿用 40 次搜索、80 次模型总预算，包含需求生成。
- 回答经连续引文校验与独立模型核验。核验无法支持的内容不作为事实展示；仍需人工打开原站判断。
- 搜索补充资料只有用户点击“确认采用”后才进入后续档案；确认会清空旧需求集合。历史报告快照不受影响。
- 报告图谱只根据保存的检索结果、名称提及、内容引文及推荐生成。快速报告的商家节点表达名称出现，不表示同一实体；完整测评仍区分门店身份。节点距离是布局结果，节点统一尺寸。
- Three.js 粒子背景、3d-force-graph、ECharts 按需加载。WebGL 不可用会回退数据表；减少动画模式关闭粒子背景与图谱自动动效。字体文件本地打包。
- 旧的 `/analyses` 与 `/runs` API 保留。新增 `/conversations`、`/conversations/{id}/messages`、`/conversations/{id}/profile`、`/chat-tasks/{id}`、`/chat-tasks/{id}/cancel`、`/chat-tasks/{id}/retry`、`/artifacts/{id}`、`/artifacts/{id}/graph`、`/artifacts/{id}/export`。完整接口见 FastAPI `/docs`。

### 查询曝光与宣传分析（2026-10-25）

- 首轮搜索词由用户的城市、品类、多个标签、区域和服务方式组合生成并保存。五条需求优先，最后一条品牌查询只补资料。更多需求可自由追问扩展。
- 检索先完成，随后才进行内容分析。未知品牌、缺少地址或模型失败不会抹去搜索结果；每条查询显示名称出现、首次页面位置、返回来源及可引用的宣传原文。
- 名称出现使用用户名称和已填别名的文字匹配，独立于同名消歧；不把它称为已确认商家曝光、推荐率或全网知名度。品牌查询与后续竞品查询不混入首轮需求计数。
- 内容线索中的商家名称和卖点都必须逐字出现在有效引文中。同批结果的商家可以用于追查，不再要求先确认其城市或门店；不据此断言竞争关系、广告合作、投放金额或营销效果。
- 报告增加“曝光与宣传”视图，以及按查询、按文章的追查入口。返回对话时带入原查询、证据及可编辑的问题。名称曝光只看搜索摘要；内容分析可读取最多3个原站正文片段，逐页显示读取时间与截断状态，不声称观看视频。
- 旧快速报告可点击“按查询重新分析”：`POST /api/v1/artifacts/{id}/reframe`，需幂等键。复用已保存查询和原始证据，不新增搜索；最多12次模型调用。创建新报告版本，保留旧报告和引用时间。用原查询集合分析，因此旧版可能仍是4条需求、2条品牌搜索。

### 文章检索与后续对话（2026-10-25）

- 首轮最多五条顾客需求由已填字段与不同消费目的组成，不混入探店、图文等文章意图。顾客需求假设不是商家服务承诺。成功检索但未见明确文章线索（包括空结果）时，最多补充两条文章追查，记录父查询与信息缺口；失败查询不自动换词重搜，追查不进入初始需求曝光计数。
- 根据已保存的标题与 URL 给出阅读提示，文章和分享线索优先展示。原搜索顺序、位置与引用 ID 保留，不把阅读排序伪装成搜索排名；类型提示尚未阅读全文核验。此展示逻辑也适用于旧报告。
- 首次输出报告卡，完整分析放在报告中。后续自由追问和竞品追查只输出聊天回答与引用，不新增 Artifact 或网络节点；需要时模型决定追加搜索。用户主动展开“更多测评工具”并启动完整实验仍可生成独立测评报告。
- 后续查询词、搜索证据与回答保存到消息和步骤中。刷新恢复后，下一轮可以继续使用近期对话证据，失败/取消的回答也保留已完成检索。不会为了保存证据自动生成新报告。


### 正文阅读与渐进图谱（2026-10-25）

- 参考 [GPT Researcher](https://github.com/assafelovic/gpt-researcher) 的来源阅读思路、[Open Deep Research](https://github.com/langchain-ai/open_deep_research) 的有界研究循环，以及 [3d-force-graph](https://github.com/vasturiano/3d-force-graph) 的折叠展开交互；保留现有 Python Worker 和元宝搜索适配器，不引入另一套 agent 框架。Open Deep Research 已归档，仅作流程参考。
- 每轮首报/追问最多读取3个不同来源 URL，搜索预算与正文读取预算分别记录。静态 HTML/文本读取不使用模型生成的 URL，只使用保存的搜索证据；每页总读取期限20秒、最多3次跳转、响应上限1MB、保存文本上限12000字符。未运行 JS、未登录，付费墙或验证页不绕过。
- `app/articles.py` 提取 article/main 文本，过滤脚本、导航及隐藏内容。连接只允许公网 HTTP(S) 标准端口，逐跳检查 DNS 地址，并固定连接到已检查的 IP，TLS 保留原主机名验证。不修改本机网络设置。
- 原摘要、排名、请求ID保持不变。正文另存为 `article`（状态、时间、URL、内容哈希、文本、截断标记或失败原因），使用 `article:<URL哈希>` 检查点恢复。正文引用须逐字存在于成功读取的片段中；模型独立审核继续执行。正文里的名称不计入摘要曝光。
- 追问可以选择已有证据读取正文而不新增搜索；成功读取的内容保留在会话证据中。普通追问仍不创建报告或图谱，旧报告不被追问修改。
- 同一个规范化 URL 在图谱中只显示一个来源节点，每条检索边保留原查询、证据ID与位置。默认仅显示查询节点，选择查询展开相关来源与名称，可切换展开全部关系。来源详情可查看不同查询下的摘要。
- 报告区分计划、尝试、成功查询数；全失败时展示查询记录和原因，默认打开可阅读视图，不显示0/0曝光。旧失败消息采用只读展示修正，历史数据不被覆盖。
- 本轮新增后端引用、缓存、重定向与URL边界、正文预算及图谱去重测试；浏览器测试覆盖桌面、手机、折叠展开、正文状态及无数据视图。所有自动化使用合成数据，真实网页提取质量需要联网复验。
